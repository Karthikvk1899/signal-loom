# API, snapshot and audit contracts

The authoritative HTTP schema is [openapi.json](openapi.json), generated by `python scripts/export_contract.py`. JSON models reject unknown properties and coercions (e.g. string percentages and boolean generations).

## Authorization

Use `Authorization: Bearer <credential>`. Bootstrap ADMIN_KEY only creates/revokes credentials and cannot access tenant APIs. Credentials bind tenant, actor, and exactly one role. Reader can list/preview/fetch; author additionally creates environments and drafts; reviewer additionally approves and activates. The API always obtains the tenant from the credential, never from a request body on tenant routes. UUID lookup includes tenant and environment. Missing/invalid/revoked bearer returns 401, wrong role 403, unknown scoped resource 404.

## Routes

| Method / route | Request and semantics |
|---|---|
| POST `/admin/credentials` | `{tenant,actor,role}`; 201 with UUID and one-time token; only token SHA-256 hash stored |
| DELETE `/admin/credentials/{id}` | Idempotent 204 revocation; admin only |
| POST `/v1/environments` | `{name}`; author; 201 or duplicate 409 |
| GET `/v1/environments` | Tenant's first 100 environments ordered by name |
| POST `/v1/environments/{env}/revisions` | `{base_generation,bundle}`; author; 201 revision UUID or stale 409 |
| GET `/v1/environments/{env}/revisions` | Latest 100 revisions, including exact bundles |
| POST `/v1/environments/{env}/revisions/{id}/approve` | No body; reviewer different from author; idempotent 200 |
| POST `/v1/environments/{env}/revisions/{id}/activate` | `{expected_generation,rollback:false}`; reviewer; 200 generation/revision; conflict 409 |
| GET `/v1/environments/{env}/snapshot` | Signed active snapshot; 404 before first release; matching If-None-Match → authenticated 304 |
| POST `/v1/environments/{env}/preview` | `{bundle,flag,subjects}`; 1–100 subjects; ordered decision results |
| GET `/v1/environments/{env}/audit?after=0` | Up to 100 ascending tenant/environment events after sequence cursor |
| GET `/v1/key` | Authenticated public signing key discovery; pin via trusted provisioning |
| GET `/health/live`, `/health/ready` | Process liveness and DB schema query; readiness unavailable → 503 |

All application responses are `Cache-Control: no-store`. HTTP/SDK callers must use TLS outside loopback development. The SDK timeout is 5 seconds and redirects are not followed. Schedule refreshes with jitter; failures do not extend the validity of cached data. No automatic retries run on the evaluation path.

## Bundle v1

```json
{"schema_version":1,"flags":[{"key":"new_checkout","enabled":true,"rollout":1000,"salt":"cohort-v1","allow":[],"deny":[]}]}
```

Defaults: schema_version=1, enabled=true, empty allow/deny. Maximum 100 uniquely named flags, 100 allow and 100 deny subjects per flag; subject length 1–256, salt 1–64 ASCII letters/digits/underscore/hyphen. Flag/environment/tenant/actor names match `^[a-z][a-z0-9_-]{0,63}$`. Rollout is integer basis points 0–10000 inclusive.

Precedence: disabled false, deny false, allow true, then hash bucket `< rollout`. Missing flag false. Hash input is canonical JSON object with `environment` (tenant/name), `flag`, `salt`, `subject`. Canonicalization uses Python json.dumps with sorted keys, separators `(',', ':')`, ensure_ascii=True, UTF-8. SHA-256 first eight bytes interpreted as unsigned big-endian integer modulo 10000. This modulo mapping is deterministic, not a guarantee of exact statistical allocation. Do not use flags to grant access; authorization remains separate.

## Signed envelope v1

```json
{"payload":{"schema_version":1,"environment":"demo/prod","generation":1,"revision":"UUID","bundle":{"schema_version":1,"flags":[]}},"signature":"BASE64_ED25519_SIGNATURE"}
```

Sign canonical payload bytes, not the envelope. Public and private keys are raw 32-byte Ed25519 keys encoded as standard base64. Signature is standard base64 of 64 bytes. Snapshot payload excludes timestamps: the database retains the exact signed envelope for each activation. ETag is quoted SHA-256 of the canonical envelope. Successful authenticated refresh or 304 advances SDK's local monotonic freshness timer; signature alone does not prove wall-clock freshness. TLS and trusted origin are required to prevent a replaying network intermediary from continually renewing an old snapshot. A fresh SDK process cannot know historical high-water marks.

## Audit event v1

```json
{"sequence":123,"created_at":"database timestamp","event":{"schema_version":1,"event_id":"UUID","action":"release.activated","actor":"bob","environment":"prod","generation":2,"revision":"UUID"}}
```

Actions: environment.created, revision.proposed (revision, base_generation), revision.approved (revision), release.activated and release.rolled_back (revision, generation). DB envelope supplies tenant scope and timestamp. Sequence is global and can contain gaps; it is not a per-tenant count. For one environment all mutations take its row lock, which orders committed events; cursors must remain scoped to that environment. There is no Kafka event or external delivery promise. Audit and the associated release write share a transaction. Administrative credential lifecycle is not included in this release audit stream.
